# BugHunt

Dev-only workstream for developing the BlueprintExporter plugin. **Not
part of any shippable distribution.** If you're consuming the plugin from
`BuiltPlugin/`, you can ignore this entire folder — it exists to exercise
the plugin in controlled conditions, not to run inside a real project.

What this folder gives you as a plugin contributor:

- A minimal UE 5.7 project (`TestProject/`) with committed fixture `.uasset`
  files under `Content/TestBlueprints/` — use it as the target `.uproject`
  for any CLI invocation (`-run=ProjectManifest`, `-run=ProjectInventory`,
  `-run=DeepDump`, etc.) while you iterate on serializers or renderers.
- A separate dev-only plugin (`BlueprintExporterTests/`) — its
  `GenerateTestBlueprintsCommandlet` regenerates the committed fixtures from
  a code-defined catalog, so when you need a new-shape fixture for a new
  typed handler or DeepRenderer, you add it to the catalog and re-run rather
  than hand-authoring.
- Plugin-discovery junctions (see below) so UBT picks up live `Source/`
  edits automatically — no need to re-sync `BuiltPlugin/` just to try a change.
- The determinism gate (`scripts/verify_determinism.ps1 -Project BugHunt`),
  which runs the full inventory pipeline twice and byte-compares the two
  output trees. This is the PR gate for any change that could affect
  inventory output.

## Relationship to the shipped plugin

The main plugin (`Source/BlueprintExporter/` + `BuiltPlugin/`) is what you
distribute to consumers. The contents of this `BugHunt/` folder are orthogonal
dev scaffolding: the test plugin points *at* the main plugin, is not part of
it, and never ships.

Running dev commandlets against `BugHunt/TestProject/` never modifies any
shipped plugin file. Fixes and features are committed against `Source/`
directly; `BugHunt/` just gives you an environment to prove them in.

## One-time local setup (gitignored, per-clone)

The `TestProject/Plugins/` folder is gitignored. UE needs the two plugins
to appear at conventional locations under the test project, and we do that
with Windows directory junctions rather than copying source.

From the repo root:

```bash
mkdir -p BugHunt/TestProject/Plugins/BlueprintExporter
cp BlueprintExporter.uplugin BugHunt/TestProject/Plugins/BlueprintExporter/BlueprintExporter.uplugin

# Scoped junctions for the shipped plugin — point at Source/ and Config/ only
# (never at the repo root, which would drag in BuiltPlugin/ and break plugin
# discovery with duplicate .uplugin files).
cd BugHunt/TestProject/Plugins/BlueprintExporter
cmd //c "mklink /J Source D:\\path\\to\\blueprint-exporter\\Source"
cmd //c "mklink /J Config D:\\path\\to\\blueprint-exporter\\Config"

# Dev-only plugin — scoped enough already, junction the whole thing.
cd ../
cmd //c "mklink /J BlueprintExporterTests D:\\path\\to\\blueprint-exporter\\BugHunt\\BlueprintExporterTests"
```

Replace `D:\\path\\to\\blueprint-exporter` with your absolute repo root.

## Build

```bash
"/d/Work/UE_DOW/engine/Build/BatchFiles/Build.bat" \
  UnrealEditor Win64 Development \
  -Project="D:\\path\\to\\blueprint-exporter\\BugHunt\\TestProject\\BugHunt.uproject" \
  -WaitMutex
```

This compiles both plugin modules against the test project. First build is
slow (rules-assembly compile + all dependencies); subsequent builds only
recompile changed files — this is the inner loop when iterating on
serializers, typed handlers, or DeepRenderers.

## Typical dev workflow: adding support for a new asset type

Concrete example: adding support for `ULevel` (Level Blueprints /
umap actors). The same shape applies for `UMontage`, `UCurveTable`, generic
`UDataAsset` subclasses, etc.

1. **Write a fixture generator.** Extend `GenerateTestBlueprintsCommandlet`
   to emit a minimal authored-content `.umap` (or whatever the asset type
   is) into `TestProject/Content/TestBlueprints/`. Commit the generated
   `.uasset`.
2. **Add a typed handler** in `Source/.../ProjectInventoryCommandlet.cpp`
   that detects the class and extracts the fields that matter (Tier 1).
3. **(Optional) Write a Tier 2 DeepRenderer** in `Source/.../TextExport/`
   following the established pattern — `LevelDeepRenderer.{h,cpp}` with a
   single `RenderLevelMarkdown(UObject*)` entry point. Wire it into
   `DeepDumpCommandlet` and `ProjectInventoryCommandlet -DeepDump`.
4. **Iterate.** Against your fixture:
   ```bash
   UE=/d/Work/UE_DOW/engine/Binaries/Win64/UnrealEditor-Cmd.exe
   PROJ='D:\\path\\to\\blueprint-exporter\\BugHunt\\TestProject\\BugHunt.uproject'

   "$UE" "$PROJ" -run=DeepDump \
     -Asset=/Game/TestBlueprints/NewFixture \
     -OutDir=./scratch \
     -nullrhi -unattended -nopause
   ```
   Read `./scratch/NewFixture.deep.md`, tweak the renderer, repeat.
5. **Prove determinism.** Before committing, run the twin-run gate:
   ```powershell
   pwsh -File scripts/verify_determinism.ps1 -Project BugHunt -SweepDeepDump
   ```
   Expect `[verify] PASS -- both output trees are byte-identical.` A FAIL
   preserves `_determinism_A/`, `_determinism_B/`, and a unified diff for
   inspection.
6. **Commit.** Source changes, new fixture, then rebuild `BuiltPlugin/` DLL
   per the root `CLAUDE.md` build loop and commit that in the same PR.

## Regenerating fixtures

`GenerateTestBlueprintsCommandlet` is idempotent by default (skips
`.uasset`s that already exist). Force-regenerate with `-Force`:

```bash
"$UE" "$PROJ" -run=GenerateTestBlueprints -Force \
  -nullrhi -unattended -nopause -nosplash -nosound
```

**Never run `GenerateTestBlueprints` against anything other than the
BugHunt test project** — it unconditionally writes into
`/Game/TestBlueprints/` and would pollute any real project's Content folder.

---

## Not the normal test loop

If you're writing automation unit tests for the main plugin (serializer
shape, type inference, JSON schema), add them under
`Source/BlueprintExporter/Private/Tests/BlueprintExporterTests.cpp` — those
are the everyday test loop and run as part of the main plugin build.
BugHunt exists for integration runs against live assets, not for unit-style
tests.

## Landmines (pre-flight reading)

1. **`BugHunt.uproject` name.** Not `BlueprintExporterTests.uproject`. UBT
   auto-generates a stub module named after the uproject when optional
   plugins make it "code-based", and that stub's class name will collide
   with any plugin module of the same name.
2. **Plugin-discovery junctions must be scoped.** Point junctions at
   `Source/` and `Config/` specifically, never at the repo root — a
   whole-repo junction drags in `BuiltPlugin/` and any `_compile_check/`
   scratch, and UBT rejects the resulting duplicate-plugin discovery.
3. **Git-bash mangles `/Game/...` arguments.** When invoking the Windows
   `UnrealEditor-Cmd.exe` from a git-bash shell, `/Game/TestBlueprints/`
   gets rewritten to `C:/Program Files/Git/Game/TestBlueprints/` before
   it reaches the exe. Prefix with `MSYS_NO_PATHCONV=1` or run from cmd.exe.
